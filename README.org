* Цель работы
1. Заменить устаревший механизм взаимодействия с сервером (XMLHttpRequest) на современный fetch с использованием Promise и async/await.
2. Собрать клиентскую часть приложения с помощью системы сборки Vite.
3. Настроить серверную часть для раздачи собранной статики, избавившись от проблем с CORS.

* Задачи
- Переписать функции обращения к API (получение, добавление, обновление, удаление программ наблюдения) с использованием fetch.
- Установить и настроить Vite в проекте.
- Настроить сборку фронтенда в папку =public=.
- Изменить сервер =server.js= для раздачи статики из =public= и поддержки SPA-роутинга.
- Убедиться в работоспособности приложения на одном порту.

* Ход работы
** Часть 1. Переход на fetch
Исходный код использовал XMLHttpRequest (или прямые импорты данных).
В файле =services/storage.js= все функции были переписаны с использованием =fetch= и =async/await=:
- =getPrograms= – GET-запрос с возможностью фильтрации через query-параметры.
- =getProgramById= – GET-запрос по id.
- =addProgram= – POST-запрос с телом в формате JSON.
- =updateProgram= – PUT-запрос.
- =deleteProgram= – DELETE-запрос.
Все функции возвращают промисы, что позволяет использовать их в асинхронных методах классов страниц (MainPage, ProductDetail). Обработка ошибок осуществляется через try-catch.

** Часть 2. Сборка через Vite
- Установлен Vite: =npm install -D vite=.
- В =package.json= добавлены скрипты:
  + =dev= : =vite= (режим разработки с горячей заменой модулей)
  + =build= : =vite build= (production-сборка)
  + =preview= : =vite preview= (превью собранного проекта)
- Создан файл конфигурации =vite.config.js=:
  #+begin_src js
  export default {
    build: {
      outDir: 'public',
      emptyOutDir: true,
    },
    server: {
      proxy: {
        '/api': 'http://localhost:3000'
      }
    }
  };
  #+end_src
  Проксирование API-запросов в dev-режиме позволяет избежать CORS на этапе разработки.
- Входной точкой клиента является =index.html=, в который добавлен тег =<script type="module" src="/main.js"></script>=.
- Проект успешно собирается в папку =public=, создавая минифицированные бандлы JS и CSS, а также копируя статические ресурсы (изображения и 3D-модели).

** Часть 3. Настройка сервера
- В =server.js= изменена строка статической раздачи: вместо корневой папки проекта теперь раздаётся папка =public=:
  #+begin_src js
  app.use(express.static(path.join(__dirname, 'public')));
  #+end_src
- Для поддержки клиентского хэш-роутинга (SPA) добавлен fallback-обработчик, который для любых не-API маршрутов отдаёт =index.html=:
  #+begin_src js
  app.use((req, res) => {
    res.sendFile(path.join(__dirname, 'public', 'index.html'));
  });
  #+end_src
  Использован =app.use()= без пути, так как Express 5 не поддерживает шаблон ="*"= в строковых маршрутах.
- Теперь фронтенд и бекенд работают на одном порту (3000), запросы к =/api/programs= выполняются без ошибок CORS.

** Возникшие проблемы и их решение
1. *Ошибка сборки из-за отсутствия модуля =three=*:
   - Причина: библиотека не была установлена.
   - Решение: =npm install three=.
2. *Ошибка сервера =Missing parameter name at index 1: *=* (Express 5):
   - Причина: Express 5 не распознаёт строковый путь ="*"= или ="/*"=.
   - Решение: заменить =app.get('*', ...)= на =app.use((req, res) => {...})=.
3. *Не отображались изображения на странице*:
   - Причина: изображения находились в корневой папке =imgs/=, которая не попадала в сборку (публичная директория Vite по умолчанию =public/=).
   - Решение: скопировать папку =imgs= в =public/imgs= или изменить конфигурацию Vite.

* Результаты

- Сервер Express отдаёт собранную статику, приложение доступно по одному адресу =http://localhost:3000=.
- Все функции (просмотр списка программ, фильтрация, добавление, редактирование, удаление, 3D-просмотр) работают корректно.
- CORS-ошибки отсутствуют.
